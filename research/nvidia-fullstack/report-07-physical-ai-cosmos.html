Physical AI / Cosmos — 세계 모델은 자율주행 개발을 어떻게 바꾸나

3장이 "차 안"의 이야기였다면 이 장은 "차를 만드는 공장", 즉 학습 컴퓨터와 시뮬레이션 컴퓨터의 이야기다. Cosmos가 무엇이고 세대별로 어떻게 바뀌었으며, Omniverse와 무엇을 나눠 맡고, 자율주행 개발에 실제로 어떻게 쓰이는지를 처음 읽는 사람도 따라갈 수 있게 정리했다.

3분 요약

Cosmos는 무엇인가?
수천만 시간의 영상을 학습해 "이 장면 다음에 세상이 어떻게 변할지"를 비디오로 만들어 내는 세계 모델이다. 쉽게 말해 데이터로 학습한 시뮬레이터다. 예측(Predict)·변환(Transfer)·추론(Reason) 세 모델로 시작해 2026년 5월 Cosmos 3 하나로 합쳐졌다 🔍.
Omniverse와는 무엇이 다른가?
Omniverse는 측량해서 그린 정밀 도면이고, Cosmos는 그 도면 위에 그림을 그리는 화가다. 기하·물리·정답 라벨·재현성처럼 정확해야 하는 것은 Omniverse가, 날씨·조명·지역처럼 많아야 하는 것은 Cosmos가 맡는다. NVIDIA 자신도 폐루프 평가의 기본값을 생성이 아닌 재구성(NuRec)에 둔다 🔍.
자율주행 개발에 어떻게 쓰나?
네 가지 패턴이다. A 라벨·시뮬 렌더를 넣고 사실적인 변주 영상을 얻는 합성 데이터, B 정책의 행동을 되먹이는 폐루프 평가, C 시뮬 롤아웃으로 정책을 고치는 강화학습, D 라벨러·채점자·주행 모델의 두뇌가 되는 추론 백본. 3장의 Alpamayo는 C와 D의 직접 사용자다.
자사(LG전자 VS)와는 어디서 만나나?
차가 아니라 개발 컴퓨터 쪽에서 만난다. Curator·Reason·Transfer·NuRec은 "데이터 공장의 설비"로 빌려 쓰고, 원재료(플릿 데이터)·품질 기준(라벨·검증 논거)·공장 운영(재수집 판단)은 우리 몫이다. 차량용 HPC 위의 Cosmos는 아직 근거가 없다 ⚠️. 세대 고정·Omniverse 의존 분리·센서 정합이 첫 결정이다(7절).
지금 어디까지 왔나?
모델은 공개(②)됐고 Foretellix·CARLA·Uber 같은 파트너 통합(③)이 진행 중이다. 그러나 자율주행에서 정량 효과가 공개된 사례는 없고, 세계 모델 시뮬 결과가 인증 근거로 쓰인 사례도 없다. NVIDIA 스스로 "부정확한 3D 구조, 비현실적 물리"를 한계로 적었다 🔍. 12개월에 4세대가 바뀌었으므로 세대 교체와 라이선스를 계획에 넣어야 한다.

0. Physical AI와 세계 모델을 먼저 쉬운 말로

이 절의 질문 NVIDIA가 말하는 Physical AI와 세계 기반 모델(WFM)은 무엇이고, 왜 자율주행에 필요하다고 하는가?

Physical AI를 가르치려면 실제 세계의 데이터가 엄청나게 필요하고, 위험한 상황일수록 데이터가 적다. NVIDIA의 답이 세계 기반 모델이다. CES 2025 발표는 이렇게 설명한다. "Physical AI 모델은 개발 비용이 크고 방대한 실세계 데이터와 테스트가 필요하다. Cosmos WFM은 기존 모델을 학습·평가하기 위한 대량의 포토리얼·물리 기반 합성 데이터를 쉽게 생성하는 방법을 제공한다" 뉴스룸 2025-01-06📄. Cosmos 자체의 정의는 GitHub에 있다. "로봇·자율주행차·스마트 인프라 등을 위한 Physical AI를 구축할 수 있게 하는 세계 모델·데이터셋·도구의 오픈 플랫폼" NVIDIA/Cosmos README🔍. 출시 당시 구성은 "생성형 세계 기반 모델, 고급 토크나이저, 가드레일, 가속 비디오 처리 파이프라인"이었다 📄.

모델은 세 갈래다. Predict1 README는 "Cosmos WFM의 세 주요 분기는 cosmos-predict, cosmos-transfer, cosmos-reason"이라고 정의한다 cosmos-predict1🔍. 각각 무엇을 넣으면 무엇이 나오는지만 기억하면 이 장의 나머지가 읽힌다.

Predict (예측)
텍스트·이미지·비디오(+행동)를 넣으면 다음에 일어날 장면을 비디오로 만든다. "이 차가 이렇게 움직이면 앞으로 어떻게 될까"를 그리는 모델.
Transfer (변환)
깊이·세그멘테이션·엣지·라이다·HD맵 같은 구조 정보를 넣으면 그 구조를 지키는 사실적인 영상을 만든다. 도면에 채색하는 모델.
Reason (추론)
영상을 보고 말로 이해하고 판단하는 언어 모델. 라벨을 달고, 생성 결과가 물리적으로 말이 되는지 채점하며, 3장 Alpamayo의 두뇌 백본이 된다.

세 대의 컴퓨터 속 위치. NVIDIA의 설명은 이렇다. "AV 개발은 세 대의 서로 다른 컴퓨터로 가능해진다. 데이터센터에서 AI 스택을 학습하는 DGX, 시뮬레이션과 합성 데이터 생성을 위해 OVX에서 도는 Omniverse, 그리고 안전을 위해 실시간 센서 데이터를 처리하는 차량 내 AGX 컴퓨터." 그리고 "3-computer 솔루션에 Cosmos가 더해지면 개발자는 수천 마일의 사람 주행을 수십억 마일의 가상 주행으로 바꾸는 데이터 플라이휠을 얻는다" NVIDIA 블로그 2025-01📄. 로봇용 설명도 같은 구조(DGX / Omniverse+OVX / Jetson AGX)다 📄.

비유로 이해하기. 비행 조종사 훈련을 생각하면 된다. 실제 비행(플릿 데이터)은 비싸고 위험하니 시뮬레이터에서 수천 시간을 탄다. Omniverse는 정밀하게 만든 물리 시뮬레이터이고, Cosmos는 "실제 비행 영상 수천만 시간을 본 AI가 즉석에서 만들어 주는 시뮬레이터"다. 후자는 만들기 쉽고 다양하지만 물리를 정확히 지킨다는 보장은 없다. 이 차이가 3절의 핵심이다.

1. Cosmos: 무엇이고 어떻게 변해 왔나

이 절의 질문 Cosmos는 정확히 무엇이고, 2025년 1월부터 2026년 9월까지 어떻게 변했으며, 지금 무엇을 써야 하나?

1.0 Cosmos란 무엇인가: 개념부터

세대 이야기로 들어가기 전에 Cosmos라는 이름이 가리키는 범위를 먼저 정한다. Cosmos는 모델 하나의 이름이 아니라 NVIDIA가 2025년 1월 CES에서 내놓은 Physical AI용 세계 모델 플랫폼의 이름이다. 저장소 정의를 다시 쓰면 "로봇·자율주행차·스마트 인프라 등을 위한 Physical AI를 구축할 수 있게 하는 세계 모델·데이터셋·도구의 오픈 플랫폼"이다 NVIDIA/Cosmos README🔍. 한 문장으로 줄이면, 수천만 시간의 영상을 학습해 "이 장면 다음에 세상이 어떻게 변할지"를 그려 내는 모델과, 그 모델을 만들고 쓰는 도구의 묶음이다.

플랫폼 안에는 여섯 부류가 들어 있다. 이 장 전체에서 이 이름들이 반복되므로 표로 정리한다.

Reason과 도구는 학습 컴퓨터(DGX), Predict·Transfer는 시뮬레이션 컴퓨터(OVX), Cosmos 3 Edge(4B)는 Jetson·Thor 같은 엣지 장치가 대상이다 🔍. 받는 곳은 GitHub(nvidia-cosmos 조직과 NVIDIA/Cosmos)와 Hugging Face 가중치, 그리고 NIM 마이크로서비스·build.nvidia.com이며, 라이선스는 1~2.5세대가 NVIDIA Open Model License, Cosmos 3가 OpenMDW-1.1이다 🔍(1.5절).

잠깐, 이름 정리. 비슷한 이름이 넷 있다. Cosmos는 플랫폼 전체, Cosmos-Drive-Dreams는 Transfer로 자율주행 합성 데이터를 만드는 파이프라인(2025-06, 2.3절), Cosmos-Dreams는 CES 2026의 마케팅명으로 공개 저장소가 없으며(패턴 B), Cosmos Curator는 데이터 정제 도구다(2.1절).
Cosmos가 아닌 것. 물리를 계산하는 시뮬레이터 엔진이 아니다(그것은 3절의 Omniverse). 주행 스택도 아니다(그것은 3장의 Alpamayo·DRIVE AV). 그리고 물리적 정확성을 보장하지 않는다. NVIDIA 스스로 "부정확한 3D 구조, 비현실적 물리 동역학"을 한계로 적었다(1.4절) 🔍.
한 줄 정리. Cosmos = 세계를 그리는 모델 셋(예측·변환·추론) + 만들고 쓰는 도구(토크나이저·가드레일·큐레이터·학습·평가) + 데이터셋. 2026년부터는 모델 셋이 Cosmos 3 하나다.

2. 데이터 파이프라인: 공장 라인으로 보기

이 절의 질문 수집한 영상이 학습 데이터가 되기까지 어떤 공정을 거치고, Cosmos는 그중 어디를 자동화하나?
개념 먼저. 데이터 파이프라인은 차가 모아 온 원시 영상을 모델이 배울 수 있는 형태로 바꾸는 공정의 연쇄다. 큐레이션은 쓸 만한 장면만 고르고 중복을 빼고 설명을 붙이는 일, 라벨링은 각 장면에 정답(무엇이 어디에 있고 왜 그렇게 운전했는지)을 다는 일, 합성 데이터는 실제로 찍지 않은 장면을 시뮬레이션이나 생성 모델로 만들어 보태는 일이다. 이 셋을 학습·평가와 이어 한 바퀴 돌게 만든 것이 데이터 플라이휠이다. Cosmos는 이 공정에서 큐레이션(Curator), 라벨링(Reason), 합성(Transfer), 평가(Evaluator)에 붙는다.

2.1 Cosmos Curator: 영상을 학습용으로 다듬는 라인

플릿에서 모은 영상은 그대로 학습에 쓸 수 없다. 장면 단위로 자르고, 정지 화면이나 저품질을 걸러내고, 무엇이 찍혔는지 글로 적고, 중복을 빼야 한다. Cosmos Curator가 이 공정을 GPU 위에서 자동으로 돌린다. 정의는 "고급 AI 모델과 분산 컴퓨팅으로 비디오 콘텐츠를 처리·분석·조직하는 강력한 비디오 큐레이션 시스템… GPU 가속 스트리밍 파이프라인에 최적화된 프레임워크 위에 구축되었고, 그 프레임워크는 Cosmos-Xenna로 별도 오픈소스화" cosmos-curator README🔍.

  1. 다운로드·디코딩·분할. 긴 영상을 장면 단위로 자른다. "TransNetV2 기반 샷 전환 분할" 또는 고정 길이 분할.
  2. 트랜스코딩. H264 mp4로 통일.
  3. 필터링. "모션·미학" 필터로 정지 화면이나 저품질을 걸러내고, 인공 텍스트 필터, VLM 기반 의미 필터·분류기를 거친다.
  4. 임베딩. InternVideo2 기본, Cosmos-Embed1(224p/336p/448p), OpenAI 호환 API.
  5. 캡셔닝. VLM(로컬 vLLM 또는 OpenAI/Gemini API)이 장면을 글로 설명하고, 캡션 보강, SAM3 추적 + 이벤트별 캡션, SeedVR2 초해상 옵션.
  6. 중복 제거. "임베딩의 K-Means 군집화와 의미 중복 제거."
  7. 샤딩. T5(t5_xxl) 텍스트 임베딩 + webdataset으로 "Cosmos 파인튜닝용 학습 준비 완료" 상태로 묶는다.

속도는 NVDEC/NVENC로 "디코딩·트랜스코딩 3배 가속"(NeMo Curator 문서), NeMo Curator 비디오 파이프라인이 "베이스라인 대비 89배, H100 2,000장으로 720p 비디오 약 100만 시간을 하루에 처리"(arXiv 2503.12964)로 요약된다 📄. NVIDIA DRIVE 페이지는 "Cosmos Curator는 대량 센서 데이터를 필터·주석·중복 제거하며 Cosmos Reason VLM을 활용해 데이터 처리 파이프라인을 수개월에서 수일로 단축"이라고 쓴다 developer.nvidia.com/drive📄. 기본 캡셔닝 모델은 문서에 명시되지 않았고 메타데이터 필드명(qwen_rejection_stage 등)으로 Qwen 계열로 추정된다 ⚠️. NeMo Curator 일반은 4장 담당이다.

2.3 자동 라벨링과 합성 데이터: 사람 손을 줄이는 두 방법

학습 데이터 제작에서 가장 비싼 것은 사람이 다는 라벨이다. Cosmos는 두 방향으로 이를 줄인다. Reason이 라벨을 달고 채점하며, Transfer가 데이터를 불린다.

Reason으로 라벨링·채점. Reason1은 2025-06-11부터 "비디오의 물리적 타당성 판단"(video critic)을 지원한다 🔍. Cookbook에는 "GR00T-Dreams에서 Cosmos Reason 2를 비디오 크리틱으로 리젝션 샘플링" 🔍과 "Cosmos Reason 2 같은 비디오-언어 모델은 강력한 자동 라벨러… (주행 결정, 핵심 요소, 인과 설명) 구조화 주석 생성"(AV 캡셔닝·VQA 레시피) 📄이 있다. Physical AI Data Factory Blueprint는 "Cosmos Evaluator(Cosmos Reason 기반)가 생성 데이터를 자동 채점·검증·필터링해 물리 정확성과 학습 준비도를 보장"하며 사용자로 "FieldAI, Hexagon Robotics, Linker Vision, Milestone Systems, RoboForce, Skild AI, Teradyne Robotics, Uber"를 든다 뉴스룸📄(발표 시점 GTC DC 2025 vs GTC 2026 상충 ⚠️). 3장에서 본 Alpamayo의 인과 사슬 라벨도 이 방식으로 만들어졌다. "Alpamayo-R1은 Cosmos-Reason을 백본으로 채택, 24.7K 큐레이션 비디오 VQA 샘플 통합"이고 의도된 용도에 "추론 기반 자동 라벨링 도구"가 들어 있으며 🔍📄, Alpamayo 2 Super의 자동 라벨 태스크와 alpamayo-coc-autolabeler 저장소가 있다 🔍.

Transfer로 불리기. Cosmos-Drive-Dreams 파이프라인은 다섯 단계다. (1) HDMap/LiDAR 깊이/World Scenario 조건 영상 렌더 → (2) Qwen3 VLM으로 프롬프트를 여러 변주로 확장 → (3) Transfer1-7B-Sample-AV로 정면 121프레임 생성 → (4) Single2MultiView로 멀티뷰 확장 → (5) VLM 필터링("coming soon") 🔍. Cookbook의 "Transfer 2.5 Sim2Real for Simulator Videos"(CARLA 증강) 🔍, Data Factory의 "실제·시뮬 입력을 증폭해 환경·조명 조건 전반의 희귀·롱테일 시나리오 포착" 📄도 같은 패턴이다.

그래서 얼마나 좋아지나. 솔직히 자율주행 쪽 수치는 확보하지 못했다. Drive-Dreams 논문은 "3D 차선 검출·3D 객체 검출·주행 정책 학습에서 롱테일 완화·일반화 향상"을 주장하지만 구체 수치는 arXiv 차단으로 읽지 못했다 ⚠️. 로봇 쪽은 Cosmos Policy "RoboCasa 71.1%(Predict2 대비 +4%)"가 있다 🔍. 벤더 블로그의 비용 추정("클립 1만 개 GPU 비용 1~1.5만 달러 vs 실수집 50만 달러 이상")은 근거가 약하다 📄⚠️.

2.4 데이터 플라이휠: 전체 루프

공정을 하나로 이으면 수집 → 큐레이션 → 라벨링 → 재구성 → 합성 → 학습 → 평가 → 갭 식별 → 재수집의 고리가 된다. NVIDIA가 "플라이휠"이라 부르는 것이다. 아래 그림과 표는 이 고리에서 Cosmos와 Omniverse가 어디에 붙는지를 보여준다. 흰 상자, 즉 수집 체계와 "무엇이 부족한가"를 판단해 다시 모으는 운영은 NVIDIA가 주지 않는다.

3. Omniverse: 무엇이고 Cosmos와 무엇을 나눠 맡나

이 절의 질문 Omniverse는 무엇이고, 둘 다 "시뮬레이션"인데 Cosmos와 무엇이 다르며, NVIDIA는 어떻게 나눠 쓰라고 하는가?

3.0 Omniverse란 무엇인가: 개념부터

Omniverse는 Cosmos보다 오래된 NVIDIA의 3D 시뮬레이션·디지털 트윈 플랫폼이다. 장면을 계산으로 만든다는 점에서 데이터로 학습한 Cosmos와 출발이 다르다. 공통 데이터 모델은 Pixar가 만든 3D 장면 기술 형식 OpenUSD이고, 그림은 RTX 광선 추적으로 그린다. 자율주행용 설명이 이를 압축한다. "물리적으로 정확한 센서 시뮬레이션을 가능하게 하는 마이크로서비스… OpenUSD 프레임워크 위에 RTX 광선 추적·신경 렌더링" ✅. 앱을 만드는 프레임워크 Omniverse Kit는 클로즈드 소스다 🔍.

자율주행 개발자가 실제로 마주치는 것은 플랫폼 전체가 아니라 그 위의 몇 가지 부품이다. 이 장에서 쓰는 이름을 표로 정리한다.

부품무엇인가자율주행에서 하는 일개방성
Sensor RTX / ovrtx카메라·레이더·라이다를 광선 추적으로 물리 시뮬레이션하는 마이크로서비스·라이브러리센서가 "보는" 것을 물리 법칙대로 계산ovrtx 0.4 프리릴리스, NVIDIA Software License(오픈소스 아님) 🔍

세 대의 컴퓨터 속 위치는 Cosmos의 Predict·Transfer와 같은 시뮬레이션 컴퓨터(OVX)다. 같은 자리에 있으면서 하는 일이 다르다는 것이 이 절의 주제다. Omniverse는 계산한다. 도로의 기하, 물체의 위치, 빛이 튀는 경로를 물리 법칙으로 풀고, 그 부산물로 "이 픽셀은 무엇"이라는 정답 라벨을 낸다. Cosmos는 학습한 대로 그린다. 물리를 풀지 않고 수천만 시간의 영상에서 배운 분포를 따라 그리므로, 다양하지만 정확성을 보장하지 않는다.

한 줄 정리. Omniverse = OpenUSD + RTX 위의 물리 시뮬레이션 플랫폼. 자율주행에서는 Sensor RTX(센서 물리), Replicator(정답 라벨), NuRec(실주행 재구성)이 쓰이고, 열려 있는 것은 3DGRUT 정도다.
비유로 이해하기. Omniverse는 측량해서 그린 정밀 도면이다. 도로의 기하, 물체의 위치, 광선이 튀는 물리를 정확히 계산하고, 그 결과로 "이 픽셀은 차, 저 픽셀은 차선"이라는 정답 라벨까지 낸다. Cosmos는 그 도면 위에 그림을 그리는 화가다. 비 오는 밤, 안개 낀 아침, 도쿄 거리처럼 외형을 무한히 바꿔 그리지만, 도면이 틀리면 그림도 틀리고 화가가 물리를 완벽히 지킨다는 보장은 없다. NVIDIA의 분담은 정확히 이것이다.

3.1 Omniverse 쪽: 물리 기반 렌더, 정답 라벨, 신경 재구성

Omniverse가 자율주행 개발에 주는 것은 세 가지다. 첫째, Sensor RTX가 카메라·레이더·라이다를 광선 추적으로 물리적으로 시뮬레이션한다. 둘째, 그 렌더 과정에서 깊이·세그멘테이션 같은 정답 라벨이 공짜로 나오고, 같은 입력이면 같은 결과가 나오는 결정론이 있다. 셋째, NuRec이 실제 주행 로그를 3D 장면으로 재구성해서, 원래 궤적과 다른 시점·다른 행동으로 다시 재생할 수 있게 한다. 이 셋째가 폐루프 평가의 기본 렌더러가 된다.

전체 그림 속 위치
시뮬레이션 컴퓨터(OVX), L4 시뮬 층.
담당 역할
OpenUSD 장면과 RTX 광선 추적으로 센서를 물리적으로 시뮬레이션하고 정답 라벨을 낸다. NuRec은 실로그를 3D 장면으로 재구성해 새 시점·궤적으로 재생한다.
현재 위치 (성숙도)
③ NuRec가 Isaac Sim 5.0(2025-08)·CARLA 0.9.16(2025-09)·AlpaSim에 통합 🔍; 3DGRUT 오픈소스(Apache-2.0) 🔍; NRE 컨테이너 26.04·nurec-skills(2026-04-30)·Instant NuRec(2026-07)·NuRec Fixer(DiffusionHarmonizer) 공개 🔍; Sensor RTX 라이브러리 ovrtx는 0.4 프리릴리스·독점 라이선스 🔍; Omniverse Kit는 클로즈드 🔍.
다음 이정표
Isaac Sim 6.0의 USD ParticleField 표준화(NuRec 전용 USDZ 폐기 예정) 🔍; NRE 컨테이너 26.04 이후 갱신 주기와 Instant NuRec의 동적 객체 지원은 미공개 ⚠️.
  • Sensor RTX. "물리적으로 정확한 센서 시뮬레이션을 가능하게 하는 마이크로서비스… OpenUSD 프레임워크 위에 RTX 광선 추적·신경 렌더링"(CVPR 2024 발표) ✅; CES 2025 조기 접근 "카메라·레이더·라이다" 📄. 오픈 라이브러리 형태 ovrtx는 "카메라·라이다·레이더 등 센서의 물리적으로 정확한 시뮬레이션", "RL in-the-loop 초당 수만 프레임부터 실시간 포토리얼 뷰포트까지"를 표방하며 0.4 프리릴리스, NVIDIA Software License(오픈소스 아님)다 NVIDIA-Omniverse/ovrtx🔍.
  • 정답 라벨과 결정론. 2022 DRIVE Sim/Replicator 블로그는 "RTX 렌더러가 RGB 카메라와 깊이·법선·세그멘테이션 정답 센서를 물리 기반 광선 추적으로 시뮬레이션… 시간 정확·결정론적이라 반복 생성 가능"하며 LED 플리커·모션 블러·롤링 셔터·라이다 빔 발산·도플러 효과를 반영한다고 썼다 📄. 2025~26 Blueprint/ovrtx에 대해 결정론을 재확인한 문장은 찾지 못했다 ⚠️.
  • NuRec. "실센서 데이터를 받아 OpenUSD로 상호작용 시뮬레이션을 재구성·렌더링하는 에이전트 친화적 3D 가우시안 스플래팅 라이브러리 집합" NuRec 페이지📄; "Isaac Sim(로봇)과 AlpaSim·CARLA(자율주행) 두 영역 지원" 📄. 오픈소스 코어는 3DGRUT(3DGRT SIGGRAPH Asia 2024 + 3DGUT CVPR 2025)로 "왜곡 카메라와 롤링 셔터 같은 시간 의존 효과를 래스터화 프레임워크 안에서 지원"하고 1차 광선 래스터·2차 광선 광선추적 하이브리드이며 USD/NuRec USDZ/PLY로 내보낸다. 2026-01 ISP 지원, 2026-06 v2.0 nv-tlabs/3dgrut🔍. 단, 재구성 서비스 자체는 CARLA에서 NVIDIA Docker 서비스로 호출되므로 소스가 아니다 🔍⚠️.
  • DRIVE Sim의 현재. 개발자 페이지는 남아 있으나 2025~26 제품 언어는 "Omniverse Blueprint for AV simulation + Sensor RTX API"다. 공식 단종·개명 선언은 없다 ⚠️.
  • Blueprint for AV simulation(CES 2025): "Sensor RTX API 등 API·서비스로 실센서 데이터에서 디지털 트윈을 구축·강화하고, 동적 물체의 물리·행동을 모델링하며, 물리적으로 정확하고 다양한 센서 데이터를 생성… 주행 데이터 재생, 새 정답 생성, 폐루프 테스트" Omniverse 뉴스룸✅. 자가 서비스 오픈소스 다운로드는 확인되지 않았다 ⚠️.

NuRec은 하나의 프로그램이 아니라 다섯 단계의 파이프라인이다(그림 11). ① 센서 로그를 오픈 데이터 표준 NCore V4로 바꾼다(변환기 내장: NVIDIA PAI·Waymo·nuScenes·PandaSet·COLMAP) NVIDIA/ncore🔍. ② 독점 NGC 컨테이너 NRE(Neural Reconstruction Engine)가 세그·깊이·ego 마스크 같은 보조 데이터를 만든 뒤, 3DGUT(왜곡 카메라를 다루는 래스터) 또는 3DGRT(광선 추적) 가우시안으로 장면을 학습한다. 다른 차량의 센서 리그로 궤적과 렌더를 옮기는 "carline adaptation"도 여기 있다. ③ 결과는 USDZ 장면(가우시안 + 리그 궤적 + 객체 트랙 + OpenDRIVE 맵)으로 나온다. ④ serve-grpc 렌더 서비스가 시뮬레이터의 "이 위치·이 시각" 요청에 RGB 프레임이나 LiDAR 스윕을 돌려주고, 객체 삽입·삭제·교체도 이 단계에서 한다. ⑤ 그 프레임을 CARLA·Isaac Sim·AlpaSim이 받는다 NVIDIA/nurec-skills🔍. 2026년에 세 가지가 더 붙었다. Instant NuRec(2026-07, Apache-2.0)은 학습 없이 피드포워드 한 번으로 10~20초 클립을 약 1.5초에 3D 가우시안으로 만들며, NRE 학습의 초기값으로 쓸 수 있다 NVIDIA/instant-nurec🔍. NuRec Fixer는 Cosmos-Predict2 0.6B 위에 만든 DiffusionHarmonizer로 공개되어 렌더 프레임의 잔상·깜빡임·삽입 객체의 조명 불일치를 정리한다 🔍. Asset Harvester(오픈)는 주행 클립의 희소 시점에서 객체별 3D 가우시안 자산을 뽑아 장면에 넣는다 🔍. 열린 것과 닫힌 것의 경계도 분명하다. NCore·3DGRUT·Instant NuRec·Asset Harvester·Harmonizer 코드는 Apache-2.0이지만, 재구성 엔진 NRE와 차량별 레시피는 NGC 키가 필요한 독점 컨테이너이고, 데이터셋은 게이트다 🔍. Isaac Sim 6.0부터는 NuRec 전용 USDZ 대신 표준 USD ParticleField가 권장되고 USDZ는 폐기 예정이다 nv-tlabs/3dgrut🔍. NVIDIA의 공식 아키텍처 도식은 docs.nvidia.com/nurec에 있으나 접근할 수 없어, 위 문서를 읽고 직접 그렸다.

잠깐, 용어. OpenUSD는 Pixar가 만든 3D 장면 기술 형식으로 Omniverse의 공통 데이터 모델이다. 3D 가우시안 스플래팅은 장면을 수백만 개의 작은 타원체(가우시안)로 표현해 빠르게 렌더하는 신경 재구성 기법이고, 3DGUT는 이를 어안 렌즈 같은 왜곡 카메라와 롤링 셔터까지 지원하도록 확장한 것(CVPR 2025)이다.

3.2 Cosmos 쪽: 생성형 변주와 증폭

전체 그림 속 위치
OVX(Transfer·Predict), DGX(Reason).
담당 역할
Omniverse/NuRec/라벨 렌더를 조건으로 받아 외형·날씨·조명·지역을 변주하고, 비디오 세계 모델로 미래를 롤아웃하며, 물리 타당성을 판단한다.
현재 위치 (성숙도)
② 모델 공개, ③ 파트너 통합(Foretellix·CARLA·Oxa) ✅.
확인 못 한 문구
"simulation vs amplification", "Omniverse produces ground truth, Cosmos multiplies"는 NVIDIA 원문 그대로 찾지 못했다 ⚠️.

역할을 가장 정확히 말하는 것은 Transfer2.5 README의 두 모드다. "Simulation 2 Real Augmentation: 3D 시뮬레이션에서 고충실도를 달성할 필요를 최소화" / "Real 2 Real Augmentation: 센서로 캡처한 RGB 증강" cosmos-transfer2.5🔍. 즉 Omniverse가 완벽한 사실감을 낼 필요가 없고, 기하와 라벨만 정확하면 외형은 Cosmos가 채운다는 분담이다. 4. 활용 패턴 4가지: 언제, 누가, 무엇을 조심해서

이 절의 질문 자율주행 개발에서 Cosmos를 실제로 어떻게 쓰나? 각 패턴은 어느 정도 검증됐나?
개념 먼저. 여기서 활용 패턴이란 "Cosmos의 어느 모델을 개발 루프의 어느 자리에 꽂는가"의 유형이다. A 합성 데이터는 학습 데이터를 불리는 자리, B 폐루프 평가는 모델이 낸 행동의 결과를 되먹여 시험하는 자리, C 정책 학습은 그 시험 결과로 모델을 고치는 자리, D 추론 백본은 라벨러·채점자·주행 모델의 두뇌로 Reason을 빌려 쓰는 자리다. 각 패턴은 성숙도가 다르므로 "누가 실제로 썼나"를 함께 본다.

네 패턴을 순서대로 보면 데이터를 만드는 일(A)에서 정책을 평가하고(B) 고치고(C) 그 두뇌를 빌려 쓰는 일(D)로 이어진다. 패턴마다 "언제 쓰나 / 누가 썼나 / 주의점" 세 가지만 답한다.

패턴 A — 합성 데이터·증강 (Transfer)

언제 쓰나. 라벨은 있지만 조건(날씨·조명·지역)이 부족할 때. 도면(라벨·시뮬 렌더)을 넣고 비·눈·안개·밤의 사실적인 영상을 얻는다. 성숙도: ② 모델·파이프라인 공개(Drive-Dreams), ③ Foretellix·CARLA·Oxa·Voxel51 통합 ✅.

대표 사례 Cosmos-Drive-Dreams. "AV 용도의 다양하고 도전적인 시나리오를 생성하기 위해 Cosmos WFM 위에 구축된 합성 데이터 생성(SDG) 파이프라인" 🔍. 실클립 5,843 → 합성 81,802(121프레임, 비·눈·안개), 4뷰(정면·좌·우·후방) 🔍. 파생 모델 5종(AV-Sample, Multiview-AV-Sample, Transfer1-Sample-AV, Single2Multiview, LiDAR-GEN) 🔍. 2025-10 LiDAR 토크나이저·디퓨전과 World Scenario 렌더링 추가 🔍. 제3자 TeraSim-World(arXiv 2509.13164)가 "포토리얼·지리 기반 센서 렌더링"에 Cosmos-Drive를 쓴다 📄.

누가 썼나. Foretellix(Foretify 시나리오 + Sensor RTX + Transfer 변주) ✅; CARLA 0.9.16 🔍; Oxa "Cosmos Transfer를 자체 툴체인 Oxa Foundry에 통합" 📄; Voxel51 "Cosmos Transfer가 만든 데이터를 관리·시각화·정제하는 툴킷(FiftyOne)" 📄.

주의점. 자율주행 다운스트림의 정량 효과 수치는 미확보 ⚠️. 라벨은 입력이므로 라벨의 품질이 결과를 결정한다.

패턴 B — 폐루프 평가·세계 모델 시뮬 (Predict / Dreams + NuRec)

언제 쓰나. 정책이 낸 행동의 결과를 되먹여 평가할 때. 렌더는 NuRec(재구성) 또는 비디오 세계 모델(생성). 성숙도: ② AlpaSim 오픈소스(2025-10), "Cosmos-Dreams" 발표(CES 2026) 📄, 공개 저장소 없음 ⚠️.

누가·무엇으로. 대표 도구는 3장에서 본 AlpaSim이다. "실제 센서 데이터·차량 동역학·교통 시나리오를 시뮬레이션해 E2E AV 정책을 폐루프로 테스트"하며 렌더러가 플러그형이라 "NuRec 기본 지원 + FlashDreams를 통한 OmniDreams 비디오 모델 렌더링"을 고를 수 있다 NVlabs/alpasim🔍. 설계 문서는 "실시간과 매우 정밀한 물리는 비목표"라고 못 박는다 🔍. Oxa는 "Cosmos Predict로 자율주행 시스템 고도화"를 말한다 📄.

근거 상세 펼치기 — AlpaSim·OmniDreams·Cosmos-Dreams 세부
  • AlpaSim: Python gRPC 마이크로서비스; 지원 정책 Alpamayo-R1·1.5, VaVAM, LTFv6(NAVSIM); 데이터 PhysicalAI-Autonomous-Vehicles-NuRec 26.01. 설계: "월드 상태가 바운딩 박스로 trafficsim에 전달되어 비자차 액터를 구동", 평가 모듈은 루프 밖에서 로그로 메트릭 계산 🔍.
  • OmniDreams(비디오 세계 모델 렌더러): "상태 유지 렌더러… 롤아웃 세션을 열고 청크 단위로 비디오 생성"; "특히 동적·비강체 물체에서 더 나은 시각 품질"; HD맵 렌더+액터 큐보이드 조건; 단일 뷰만 지원; VRAM 48GB(FlashDreams)/96GB(Alpamayo1.5); 카메라 오버라이드 시 "생성 비디오가 드리프트·정렬 이탈 가능"; 기반 Cosmos 모델명 미기재 VIDEO_MODEL.md🔍.
  • Cosmos-Dreams(CES 2026 마케팅명): "대규모로 희귀·롱테일 주행 시나리오를 시뮬레이션하는 포토리얼 폐루프 AV 시나리오 생성 세계 모델" 📄. nvidia-cosmos 조직에 cosmos-dreams 저장소는 없다(2026-09-02 확인) 🔍. AlpaSim의 OmniDreams/FlashDreams가 구현 표면으로 추정된다 ⚠️.
  • Predict 멀티뷰: Predict2.5 2B/auto/multiview(7카메라) 🔍.

주의점. NVIDIA 자신의 폐루프 평가 기본값은 생성이 아니라 재구성(NuRec)이다(저장소 기본값에서 추론) 🔍. 생성 렌더러는 단일 뷰이고 드리프트할 수 있다.

패턴 C — 정책 학습·강화학습 (Cosmos-RL, AlpaGym)

언제 쓰나. 시뮬 환경에서 롤아웃을 돌려 정책(VLA)을 강화학습으로 후학습할 때. 3장 Alpamayo 1.5의 강화학습이 이 패턴의 실사용이다. 성숙도: ② Cosmos-RL(유지보수)·AlpaGym(2026-06, "초기 활발 개발") 🔍.

  • Cosmos-RL: 정책/롤아웃 replica 비동기, TP/SP/CP/FSDP/PP 병렬, FP8 학습·FP8/FP4 롤아웃, 단일 컨트롤러·동적 NCCL 그룹 🔍. 3장의 Alpamayo 오픈루프 RL(GRPO, 640 GPU) 레시피가 이를 쓴다 🔍.
  • AlpaGym: AlpaSim=환경, Cosmos-RL=분산 롤아웃·학습, 보상 예 progress_safety, Alpamayo 1.5(10B)만 지원, 처리량 수치 미공개 🔍.
  • 로봇 쪽 대응(맥락): GR00T-Dreams는 "Cosmos WFM으로 이미지 1장+언어 지시에서 대량 합성 궤적 생성" → IDM으로 행동 추출 → GR00T N1 파인튜닝 NVIDIA/GR00T-Dreams🔍; Cosmos Policy "LIBERO 98.33%, RoboCasa 71.1%" 🔍. Jetson Thor는 DRIVE Thor와 같은 SoC 계열이다 📄(1장).

주의점. 자율주행용 폐루프 RL(AlpaGym)은 아직 초기이고 처리량 수치가 없다. 시뮬 환경의 물리·렌더 오류가 보상 오류로 이어진다.

패턴 D — 추론 VLM 백본 (Reason)

언제 쓰나. 라벨러·크리틱·플래너의 두뇌가 필요할 때. 성숙도: ③ Alpamayo 1/1.5/2 Super 백본으로 채택(NVIDIA 내부 양산 파이프라인) 🔍.

  • 백본: Alpamayo "Cosmos-Reason 백본 + action expert" 🔍; 세대 매핑 Reason1 → Reason2 → Cosmos 3 Super Reasoner(3장) 🔍.
  • 크리틱: Reason1 video critic 🔍, Reason2 리젝션 샘플링 🔍, Cosmos Evaluator 📄.
  • 라벨러: AV 캡셔닝·VQA 레시피 📄, 3D AV 그라운딩 후학습 레시피 🔍, Curator의 Reason 활용 📄.

주의점. 백본이 세대마다 바뀐다(Qwen2.5-VL → Qwen3-VL → Cosmos 3 MoT). 파인튜닝 자산이 세대 교체에 묶인다.

7. 자사 관점: LG전자 VS와의 접점과 협업 고려사항

이 절의 질문 차량용 HPC와 AI 플랫폼을 개발하는 LG전자 VS사업본부(이하 VS)가 이 장을 읽으면 무엇이 특이하고, Cosmos·Omniverse와 어디서 만나며, 도입·협업할 때 무엇을 따져야 하나?

이 절은 앞의 조사 결과를 자사 관점으로 다시 읽은 것이다. NVIDIA 쪽 사실은 0~6절의 출처를 그대로 따르고, LG 쪽 사실은 3장 8절에서 쓴 공개 발표 세 건(IVI+Hyperion 통합, LG이노텍 부품, aiMotive 통합 컨트롤러)만 쓴다. VS의 내부 계획은 공개 자료로 알 수 없으므로 그에 기대는 판단은 모두 추정(⚠️)으로 표시했다. 3장의 자사 관점이 "차 안의 스택"이었다면, 이 절은 "차를 만드는 공장", 즉 학습·시뮬레이션 컴퓨터 쪽의 접점이다.

7.1 이 장의 특이사항 여섯 가지

  1. Cosmos는 제품이 아니라 개발 도구다. 차에 들어가는 Cosmos는 아직 없다. Cosmos 3 Edge 4B가 Jetson·Thor를 대상으로 하지만 차량 적용은 미확인이다(1.4절). 접점은 차량이 아니라 개발 컴퓨터 쪽에 생긴다.
  2. 12개월에 4세대, 라이선스는 두 갈래. 이전 저장소는 전부 유지보수 모드이고, 1~2.5세대는 NVIDIA Open Model License(가드레일 우회 시 종료·표시 의무), Cosmos 3는 OpenMDW-1.1이다(1.5절). 어느 세대에 파이프라인을 고정하느냐가 곧 컴플라이언스와 이관 비용이다.
  3. 정확해야 하는 것은 Omniverse, 많아야 하는 것은 Cosmos. NVIDIA 자신도 폐루프 평가의 기본값을 생성이 아닌 재구성(NuRec)에 두고, 세계 모델 시뮬 결과가 인증 근거로 쓰인 사례는 없다(3.4절, 4.6절).
  4. 도구는 열렸지만 데이터와 판단은 사용자 몫. Curator·Reason·Transfer가 큐레이션·라벨링·합성을 자동화해도, 수집 체계와 "무엇이 부족한가"를 판단해 다시 모으는 운영은 NVIDIA가 주지 않는다(2.4절). 자율주행 다운스트림의 정량 효과 수치도 공개된 것이 없다(2.3절).
  5. 개방성 편차가 크다. 3DGRUT와 Cosmos 코드는 오픈소스지만, Sensor RTX 라이브러리(ovrtx)·Omniverse Kit·NuRec 재구성 서비스는 독점이고 데이터셋은 게이트다(3.1절). "오픈 플랫폼"이라는 말과 실제 의존 지점은 다르다.
  6. 채택사 명단에 Tier-1이 없다. 공개 진술이 있는 사용자는 Uber·Foretellix·CARLA·Wayve·Waabi·Plus·Oxa·Voxel51 같은 로보택시·시뮬 벤더다(4절). Bosch·Magna 같은 Tier-1의 Cosmos 사용 진술은 찾지 못했다 ⚠️. 선례 없이 시작하는 자리라는 뜻이다.

7.3 협업 시 고려사항

  1. 세대 기준을 고정한다. 새로 시작한다면 Cosmos 3(OpenMDW-1.1)이 기준이고, 1~2.5세대는 유지보수 모드에 NOML 조건이 붙는다. 다만 자율주행 특화 자산(Transfer2.5 7뷰 auto multiview, Drive-Dreams, Predict2.5 멀티뷰)은 아직 2.5세대에 있으므로, Cosmos 3 Transfer 컨트롤로의 이관 시점을 정해야 한다 🔍.
  2. Omniverse 의존 지점을 분리한다. 재구성(NuRec 서비스)·센서 물리(ovrtx)는 독점이다. 오픈된 3DGRUT과 CARLA 통합을 대안으로 병행하고, 어느 공정이 NVIDIA 서비스 없이는 멈추는지 표로 남긴다 🔍.
  3. Cosmos의 자리를 "학습 데이터·탐색"으로 한정한다. 인증 근거는 Omniverse·실차·자체 SIL/HIL로 두고, 세계 모델 시뮬은 롱테일 탐색과 데이터 증강에 쓴다. NVIDIA 자신의 평가 기본값이 재구성이라는 점이 근거다 🔍.
  4. 센서 정합을 먼저 본다. 공개 데이터셋·멀티뷰 체크포인트는 7카메라 f-theta 기준이다. 자사 카메라 구성이 다르면 Transfer·Predict 멀티뷰와 Alpamayo 입력 프로파일을 함께 재학습해야 한다 ⚠️.
  5. 정량 효과는 자체 실험으로 확인한다. 합성 데이터의 자율주행 다운스트림 개선 수치는 공개된 것이 없다. 도입 전에 자사 태스크(차선·객체 검출, 정책)에서 A/B 실험을 설계해야 한다 ⚠️.
  6. 데이터 주권·라이선스. Physical AI 데이터셋은 게이트·NVIDIA AV Dataset License, 가드레일 비활성화는 "라이선스 준수는 사용자 책임"이다. 자사 플릿 데이터를 NVIDIA 도구에 넣을 때의 소유권·개인정보 처리는 계약으로 정한다 🔍.
  7. 컴퓨트 예산을 사이클 단위로 잡는다. 한 번의 생성이 아니라 "수집 → 큐레이션 → 합성 → 학습 → 평가"가 반복되는 비용이다. 7뷰 Transfer와 대형 Reason 추론은 H100급 다수를 요구한다 🔍.
  8. 선례가 없다는 점을 계획에 넣는다. Data Factory Blueprint 사용자와 Cosmos 채택사에 Tier-1은 없다. Uber·Foretellix가 걸어간 길(시나리오·검증 툴체인 통합)이 가장 가까운 참고이며, 데이터 엔지니어링·시뮬 인력을 선행 확보해야 한다 📄⚠️.
