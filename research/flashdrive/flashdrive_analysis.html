01핵심 요약

문제 → 해결 → 결과

💡 본문의 점선 밑줄 용어에 마우스를 올리면 해설이 나타난다. 전체 정리는 §09 용어 해설.

한 줄 요약: "생각하는" 자율주행 AI는 너무 느렸다(스텝당 0.7초). FlashDrive는 추론 파이프라인 곳곳에 숨은 낭비를 각각 제거해, 정확도 손실 없이 4.5배 빠른 159ms — 실시간에 근접한 속도 — 를 만들었다.

문제 — 추론에는 시간이 든다

최신 자율주행 VLA 모델은 chain-of-thought 추론으로 희귀 상황(long-tail)을 단계별로 "생각"한다 — 대표가 NVIDIA Alpamayo 1.5(10B, Qwen3-VL 기반). 그런데 이 "생각" 때문에 스텝당 716ms(~1.4Hz), 실시간 주행 요구에 크게 미달. 게다가 병목이 인코딩(88ms)·프리필(177ms)·디코딩(264ms)·액션 생성(187ms) 네 단계에 고르게 분산되어, 한 단계만 고쳐서는 도달 불가.

해결 — 단계마다 다른 중복성을 각개격파
  • Streaming Inference (Encode/Prefill) — 연속 스텝 간 카메라 프레임 75% 중복 → KV 캐시 재사용으로 새 프레임만 처리
  • Speculative Reasoning (Decode) — 주행 추론 토큰(~16개)은 뻔하다(낮은 엔트로피) → DFlash 블록 드래프트로 8토큰씩 제안·검증
  • Adaptive Flow Matching (Action) — 디노이징 중간 스텝의 속도가 거의 불변(코사인 유사도 0.99+) → 중간 스텝 속도 캐싱
  • W4A8 양자화 (ParoQuant) (Prefill+Decode) — 가중치의 수치적 여유 활용, 이상치 억제로 CoT 누적 오차 통제
  • 시스템 최적화 (전 단계) — CUDA Graphs + 커널 융합

중복성들이 서로 직교(다른 단계, 다른 원인)라서 가속이 상쇄 없이 누적된다.

결과 — 4.5× 가속, 정확도는 소폭 개선
  • 지연: 716ms → 159ms (4.5×), 모든 단계 3.4~7× 가속 (RTX PRO 6000)
  • 정확도: ADE@6.4s 1.72m → 1.56m (개선), minADE 0.77 → 0.84m (0.1m 이내)
  • 범용성: Jetson Thor~데이터센터 GPU 5개 플랫폼 4.0–5.7× 일관 가속, 단일 구현
  • 재현성: MIT 코드 + HF 체크포인트 공개. sub-200ms = 실시간 VLA 주행 배포의 진입점
시사점 — 무엇이 열렸고, 무엇이 남았나

열린 것: "추론형 VLA는 느려서 못 쓴다"는 전제가 깨짐. 분산된 병목도 단계별 도메인 지식으로 각개격파하면 곱셈적 가속이 됨을 실증 — 주행 너머 로봇 등 지연이 제약인 모든 VLA에 적용 가능한 템플릿. "오차에 민감한 action expert만 보호하라"는 발견은 VLA 압축의 실무 레시피 감.

남은 것: 실차 하드웨어(Jetson Thor)에선 944ms(~1Hz)로 실시간 미달 · 공개 지표가 open-loop 평균뿐(최악 지연·전력·closed-loop 안전성 미공개) · 논문 미공개라 기법별 기여 분해 검증 불가. 상세는 §06, 실차 관점 §07, 활용법 §08.

02등장 배경

"추론에는 시간이 든다"

전통적 자율주행은 인지와 계획을 분리한 모듈식 구조라, 희귀하고 복잡한 long-tail 시나리오에서 취약하다. Vision-Language-Action(VLA) 모델은 chain-of-thought 추론을 end-to-end 주행에 통합해 낯선 상황을 단계별로 "생각"하고, 명시적 추론 흔적과 궤적 예측을 함께 내놓는다.

NVIDIA는 2026년 1월 CES에서 업계 최초의 오픈소스 추론형 주행 VLA인 Alpamayo 1을 발표했고, 이어 Alpamayo 1.5를 공개했다. Chain-of-Causation(인과 연쇄) 추론으로 각 주행 결정을 해석·감사할 수 있게 만든 것이 핵심이다. 문제는 비용: Alpamayo 1.5는 RTX PRO 6000에서 스텝당 716ms, 약 1.4Hz — 안전 주행의 실시간 요구에 한참 못 미친다.

누가 만들었나 — Z Lab은 UCSD ML Systems Group 산하의 효율 AI 풀스택 연구실(z-lab.ai). PI Zhijian Liu는 UCSD 조교수 + NVIDIA Research Scientist 겸직으로, MIT 박사 후 자율주행 인지 대표작 BEVFusion(ICRA 2023, 공동 1저자)과 효율 VLM 계열(NVILA·SparseVILA)을 거쳤다(약력) — NVIDIA 모델을 최적화 대상으로 고른 맥락과 "자율주행 × 효율 추론"이라는 주제가 이 이력에서 자연스럽게 나온다.

FlashDrive는 단독 성과가 아니라 Z Lab의 효율 추론 스택을 주행 VLA에 집약한 결과다. 아래 둘은 같은 랩이 먼저 발표한 범용 LLM 가속 기법으로, FlashDrive가 부품처럼 가져다 쓴다: 디코딩 가속의 DFlash(ICML 2026), 양자화의 ParoQuant(ICLR 2026)가 구성 요소로 들어간다.

03문제 정의

병목은 한 곳이 아니라 모든 곳에 있다

VLA 주행 모델의 추론은 4단계로 나뉜다: 비전 인코딩 → 프리필 → 디코딩 → 액션 생성. 저자들이 Alpamayo 1.5를 프로파일링한 결과, 지연이 4단계에 고르게 분산되어 있었다. Decode+Action이 전체의 약 2/3이지만 Encode/Prefill도 무시할 수 없어, 단일 단계 최적화로는 실시간 도달이 불가능하다 — "algorithm-system co-design"이라는 접근의 근거다.

04방법론

다섯 개의 중복성, 다섯 개의 지름길

1. Streaming Inference — 시간적 중복 (Encode/Prefill)

주행 VLA는 매 스텝 슬라이딩 윈도(예: 4프레임 × 4카메라 뷰)를 입력받는데, 연속 스텝 간 프레임의 75%가 겹친다. 새 프레임만 처리하도록: 이전 3프레임의 KV 캐시 재사용(비전 연산 75% 제거), 프레임 퇴출·도착에 따른 위치 이동을 즉석 rotary embedding으로 처리하는 pre-RoPE key 캐싱, view-major 토큰 순서에서 인과성을 지키는 커스텀 스트리밍 어텐션 마스크.

핵심 통찰 — 비대칭 미세조정 스트리밍 캐시는 근사라 정확도가 떨어진다(ADE 1.85→2.30m). 직관적 해법인 VLM 전체 미세조정은 오히려 크게 악화(4.97m). 추론 토큰은 최근 토큰 위주로 어텐션해 오래된 캐시에 강건하지만, action expert는 cross-attention으로 캐시 전체를 통합해 작은 분포 불일치도 증폭하기 때문. 해법: VLM은 동결, action expert만 미세조정 — 무그래디언트 롤아웃으로 배포 시의 누적 오차에 노출시킨 뒤 마지막 스텝만 학습. ADE 1.93m으로 기준선 근처 회복.

2. Speculative Reasoning — 낮은 엔트로피 (Decode)

주행 추론 시퀀스는 짧고(~16토큰), 구조화된 템플릿을 따르며, 풍부한 시각 컨텍스트가 내용 대부분을 이미 결정한다 → 토큰당 엔트로피가 낮아 speculative decoding의 수락률이 높다. 자체 개발한 DFlash(블록 확산 모델)를 드래프터로 사용. 기존 드래프터(EAGLE 계열)처럼 토큰을 하나씩이 아니라 한 번의 forward로 8토큰 블록을 통째로 제안하고 타깃이 한 번에 검증한다. Speculative verification은 출력 분포 동일성을 보장하므로 품질 손실 0.

3. Adaptive-Step Flow Matching — 속도장 평탄성 (Action)

궤적 생성에 쓰이는 flow matching 헤드의 표준 10 디노이징 스텝을 프로파일링하니 U자형 패턴: 속도 변화가 0→1 스텝에서 27%, 중간 스텝에서 6% 미만(코사인 유사도 0.99+), 마지막에 다시 상승. 물리적 해석 — 초기 스텝은 거시 구조(차선·회전 방향)를 결정, 마지막 스텝은 운동학 제약을 만족하는 궤적 매니폴드에 스냅, 중간은 미세 조정뿐. "끝점이 신호를 담고, 중간은 관성만 담는다." 중간 스텝의 속도를 캐싱·재사용해 action expert forward를 건너뛴다.

4. W4A8 Quantization (ParoQuant) — 수치적 여유 (Prefill+Decode)

두 가지 설계 선택이 핵심이다.

  • 왜 W4A16이 아닌 W4A8인가: 표준 W4A16(AWQ류)은 메모리 바운드인 디코딩만 돕는다. VLA는 매 프롬프트에 수천 개의 비전 토큰이 있어 컴퓨트 바운드인 프리필을 무시할 수 없다. 4비트 가중치로 디코딩 대역폭을, 8비트 활성값의 INT8 행렬곱으로 프리필을 동시 공략 — "One format, two bottlenecks addressed."
  • 왜 ParoQuant인가: CoT 토큰이 매번 모델에 피드백되어 양자화 오차가 누적된다. AWQ는 이상치를 부분 처리해 잔여 오차가 궤적 드리프트로 쌓이지만, ParoQuant의 scaled pairwise rotation이 이상치를 더 철저히 억제한다.

구현: vLLM의 Marlin 커널로 INT4/INT8 실행, action expert는 bf16 유지 — 기법 1의 통찰(expert의 오차 민감성)과 일관된 설계.

5. System Optimizations — 디스패치 오버헤드 (전 단계)

CUDA Graphs: 자동회귀 생성의 수많은 소형 커널 런치 오버헤드를, 4단계 파이프라인 전체를 그래프로 컴파일해 제거(torch.compile + 정적 KV 캐시). Kernel Fusion: Q/K/V 프로젝션 융합, MLP gate/up 병합, max-autotune 컴파일로 메모리 왕복과 런치 공백 제거.

05실험 결과

모든 단계가 빨라지고, 이득은 곱해진다

어떤 단일 최적화도 전체 가속의 절반을 넘지 않는다 — 중복성이 직교하므로 이득이 포화 없이 누적된다는 핵심 주장을 뒷받침한다. 정확도는 ADE@6.4s 1.72 → 1.56m(소폭 개선), minADE@6.4s 0.77 → 0.84m(0.1m 이내 변동).

06평가

의의와 한계 (상세)

의의

  • 실시간 추론형 VLA의 실용화 진입점 — 716ms(1.4Hz)는 계획 주기마다 새 결정을 낼 수 없는 속도였고, 159ms(≈6.3Hz)부터 주행 계획 루프와 맞물리기 시작한다. 뒤집으면 같은 지연 예산으로 더 큰 모델·더 긴 추론·더 많은 후보 궤적을 돌릴 여유가 생겼다는 뜻. 로봇 등 같은 구조(비전 스트림+짧은 추론+연속 제어)의 타 도메인 VLA에도 이식 여지가 크다.
  • "직교하는 중복성" 프레임의 방법론적 가치 — 프로파일링으로 "단일 병목 없음"을 먼저 보이고, 단계마다 다른 중복성을 다른 도구로 제거. 어떤 단일 기법도 전체 가속의 절반을 못 넘는데 곱해져 4.5× — "은탄환 없음, 스택 전체 공략"이라는 VLA 서빙 최적화 체크리스트를 제시.
  • 도메인 지식 × 시스템 최적화의 결합 모범 — LLM 서빙 기법을 그대로 이식하지 않고 주행 특성으로 재보정: 프레임 75% 중복→streaming, 16토큰 템플릿 추론→높은 speculative 수락률, U자 속도장→선택적 스텝 캐싱, 수천 비전 토큰 프리필→W4A8. "도메인 인지형 서빙 최적화"의 사례 연구.
  • action expert 오차 민감성 — 새로운 관찰 — 근사에 대한 내성이 모듈별로 비대칭(추론 토큰은 강건, cross-attention expert는 증폭). VLM 전체 미세조정이 오히려 악화(4.97m)라는 반직관적 결과 포함, "압축·근사 시 액션 헤드를 보호하라(expert만 미세조정·expert만 bf16)"는 설계 원칙 도출 — 후속 VLA 연구에 인용될 만한 기여.
  • 재현 가능성·개방성 — MIT 코드 + 모델 2종×3형태(base/W4A8/드래프터) 체크포인트 6개 + 벤치 스크립트. 산업계가 자사 환경에서 직접 검증 가능한 형태.
  • 두 모델에서의 일관성 — Alpamayo 1과 1.5 모두 4.5×/4.7× 가속 + minADE 동반 개선 → "정확도 유지"를 단일 모델 요행으로 보기 어려움.

한계·유보

  • 논문 미공개 — 검증의 최대 공백 — 기법별 기여 분해(ablation 전체), 평가 프로토콜(minADE 스케일 불일치 0.77 vs 1.705), 관련 연구 정량 비교 확인 불가. 수치 전부 저자 자체 보고, 동료 심사 여부 미확인.
  • 실차 하드웨어에선 실시간 미달 — Jetson Thor 944ms(≈1.06Hz). sub-200ms는 워크스테이션 GPU 기준. 실차 실시간까지 Thor 기준 추가 약 5× 필요(분석).
  • 평균 지연만 공개 — 최악 지연 미보고 (분석) — speculative 수락률·추론 토큰 수에 따라 지연이 가변인데 분포·상한 미공개. 실시간 안전 시스템은 평균이 아닌 결정적 상한(WCET)을 요구.
  • 전력·발열·메모리 미공개 (분석) — 차량 전장의 빠듯한 전력·열 예산 대비 평가 불가.
  • 근사 기법의 안전 검증 부담 (분석) — speculative는 무손실이지만 스트리밍 캐시·양자화·스텝 캐싱은 분포를 바꾸는 근사. 공개 지표는 open-loop 평균뿐 — closed-loop, 안전 시나리오, 그리고 아이러니하게도 VLA의 존재 이유인 long-tail 희귀 상황 성능이 미검증. 평균 ADE 유지 ≠ 꼬리 분포 유지.
  • 스트리밍은 공짜가 아님 — action expert 재학습 필요 → 기반 모델 업데이트마다 미세조정 파이프라인 재실행, zero-shot 적용 불가.
  • 대상 모델 특이성 — Alpamayo 계열 2종(10B, Qwen3-VL, flow matching 헤드)에서만 검증.
  • 라이선스 — 코드 MIT, Alpamayo 가중치는 NVIDIA 비상업 → 상용 적용엔 별도 협의 필요.

07심화 · 실차 적용

실제 차에 올릴 수 있나

공개 수치 기반 분석적 평가 — 출처 표기 없는 판단은 필자 분석.

제어 주기와의 간극

자율주행 계획 모듈은 통상 10Hz 내외로 도는 것이 일반 관행. FlashDrive 적용 후에도 워크스테이션 GPU 6.3Hz, 실차용 Jetson Thor 1.06Hz — VLA를 "매 주기 궤적 생성기"로 쓰기엔 실차 기준 부족하다. 다만 출력이 6.4초 시계의 궤적이라, 상위 계획자(저주기 VLA) + 하위 트래킹 제어기(고주기 고전 제어) 구조라면 1Hz급 갱신도 성립 가능(분석).

현실적 배치 시나리오 (분석)

시나리오구조FlashDrive의 기여
계층형VLA가 1~6Hz로 상위 궤적·의도 결정, 하위 10Hz+ 고전 제어기가 트래킹4~5× 가속으로 상위 루프를 실용 주기로
온디맨드평시 고전 스택 주행, long-tail 상황 감지 시 VLA 호출개입 지연 716→159ms 단축
병행·감사VLA가 병렬로 주행 결정을 검증·설명(reasoning trace 로깅)실시간 병행 실행 가능성 확보
개발 인프라데이터센터에서 대규모 시뮬레이션·자동 라벨링·리플레이GPU당 처리량 4.5× = 비용 ÷4.5

인증·안전 관점의 숙제 (분석)

  • 결정적 지연 — 안전 실시간 시스템은 최악 실행 시간 보장이 필요. speculative 가변성에 대한 상한 설계와 타임아웃 폴백 명세 필요.
  • 근사의 변경 영향 분석 — 스트리밍 캐시·양자화·스텝 캐싱은 기능 안전 프로세스(ISO 26262류) 관점에서 "원 모델과 다른 소프트웨어". 무손실인 speculative와 달리 별도 검증 논거 필요.
  • long-tail 검증 — VLA 채택 이유가 희귀 상황 대응인데, 근사 기법들이 바로 그 상황에서 잘 동작하는지는 평균 ADE로 알 수 없음. closed-loop·시나리오 기반 평가가 선행돼야 실차 논의 가능.
  • 전력·발열 실측과 가중치 라이선스(비상업) 해결도 전제 조건.
그래서 실차에 언제? FlashDrive의 실차 의미는 "오늘 바로 탑재"가 아니라 간극을 소프트웨어만으로 4~5× 줄였다는 것. Thor에서 남은 ~5×는 모델 축소·증류 × 더 공격적 압축 × 차세대 차량 SoC가 곱해지면 도달 가능한 범위 — "추론형 VLA 실차 탑재"를 연구 과제에서 엔지니어링 로드맵 문제로 바꿔 놓았다. (분석)

08심화 · 활용 가이드

개발자 관점: 어떻게 쓸 수 있나

바로 실행 — 재현·평가

요구 환경: CUDA 12.8, Python 3.12, compute capability 8.0+ GPU (README). 체크포인트 경로만 바꿔 최적화/원본을 스위치하는 구조라 자기 GPU에서 베이스라인 대비 이득을 바로 실측할 수 있다.

git clone https://github.com/z-lab/flashdrive && cd flashdrive
uv venv --python 3.12 && source .venv/bin/activate && uv sync

python scripts/infer.py --model-path z-lab/Alpamayo-1.5-10B    # 최적화 스택
python scripts/infer.py --model-path nvidia/Alpamayo-1.5-10B   # 원본 베이스라인
import flashdrive
model = flashdrive.from_pretrained("z-lab/Alpamayo-1.5-10B")
pred_xyz, pred_rot = model.sample_trajectories_streaming(data)  # 첫 호출은 캐시 프리필만

부품별 이식 — 자기 VLA에 적용하는 체크리스트 (분석)

코드가 기법별 모듈(streaming.py, dflash.py, quantization.py, diffusion.py, fusion.py)로 나뉘어 개별 이식이 쉽다.

  1. 입력이 연속 멀티프레임 스트림? → streaming inference 후보. 단 action expert 미세조정 파이프라인 각오(zero-shot 불가).
  2. 출력 추론이 짧고 템플릿화? → speculative 수락률 높을 조건. DFlash 드래프터 학습 필요(또는 EAGLE류로 시작).
  3. 액션 헤드가 diffusion/flow matching? → 자기 모델 속도장을 프로파일링해 U자 확인 후 캐싱 스텝 선정. 균일 스텝 축소보다 안전.
  4. 양자화는 W4A8 + 민감 모듈 제외 — 프리필 무거운 멀티모달이면 W4A16보다 W4A8, 액션 헤드는 bf16 유지가 이 논문의 레시피.
  5. 시스템 최적화는 마지막 — CUDA Graph·커널 융합은 알고리즘 확정 후(구조 변경마다 재컴파일).

DFlash·ParoQuant는 독립 사용 가능 — DFlash는 SGLang(프로덕션)·Transformers(탐색) 지원(DFlash 페이지), ParoQuant는 자체 repo·HF 컬렉션(논문). 주행 VLA가 아닌 일반 LLM 서빙에도 각각 적용 가능.

그 외 (분석)

  • 벤치마크 기준선 — 공개 코드+모델+데이터셋 조합이라 VLA 서빙 연구의 비교 대상으로 적합.
  • 프로파일링 방법론 차용 — "4단계 분해 → 병목·중복성 식별 → 직교 기법 매핑" 절차 자체를 자기 파이프라인에 적용.
  • 주의 — Alpamayo 가중치는 비상업 라이선스: 사내 연구·평가 가능, 제품 탑재는 별도 협의. FlashDrive 코드(MIT)는 자유.

09용어 해설

이 분석에 나오는 기술 용어

VLA (Vision-Language-Action)
카메라 영상을 이해하고(Vision), 언어로 상황을 추론한 뒤(Language), 실제 제어 행동 — 여기서는 주행 궤적 — 까지(Action) 한 모델에서 출력하는 통합 모델. "보고 → 말로 생각하고 → 움직이는" 모델.
Chain-of-Thought (CoT) / Chain-of-Causation (CoC)
답을 바로 내지 않고 중간 추론 과정을 텍스트로 생성하며 단계별로 생각하는 기법. Alpamayo의 CoC는 "정지 표지판이 있다 → 교차로가 통제된다 → 정지한다"처럼 인과 관계로 연결된 주행 특화 추론.
추론 4단계: Encode / Prefill / Decode / Action
① Encode — 카메라 이미지를 토큰(숫자 벡터)으로 변환. ② Prefill — 비전 토큰 + 프롬프트 전체를 한 번에 병렬 처리해 문맥 구축(첫 토큰 생성 전 준비). ③ Decode — 추론 텍스트를 토큰 하나씩 순차 생성(자동회귀, 가장 느림). ④ Action — 추론 결과로 주행 궤적(좌표열) 생성.
KV 캐시 (Key-Value cache)
Transformer 어텐션에서 토큰마다 만들어지는 Key/Value 벡터의 저장소. 한 번 계산한 것을 보관해 재계산을 피한다. FlashDrive는 이를 카메라 프레임 단위로 확장 — 이미 본 프레임의 K/V를 다음 스텝에 재사용해 비전 연산 75% 제거.
RoPE / Pre-RoPE 캐싱
RoPE는 토큰 위치를 벡터 회전으로 새기는 기법. 슬라이딩 윈도에서 프레임이 빠지면 위치 번호가 바뀌어 캐시가 무효화되는데, 위치를 새기기 전(pre-RoPE) 상태로 캐싱하고 사용 시점에 즉석으로 새기면 해결된다.
자동회귀 (autoregressive) 디코딩
토큰을 한 번에 하나씩, 이전 출력을 입력에 더해가며 순차 생성하는 방식. 병렬화가 안 되어 LLM 추론에서 가장 느린 구간.
엔트로피 (토큰당)
다음 토큰의 예측 어려움 척도. 주행 추론은 짧고 템플릿화되어 있고 시각 정보가 내용을 거의 결정하므로 엔트로피가 낮다 = 다음 토큰이 뻔하다 = 작은 모델이 미리 맞히기 쉽다.
Speculative decoding (추측 디코딩)
작은 "드래프터" 모델이 다음 토큰들을 미리 추측하고, 큰 타깃 모델이 한 번의 병렬 forward로 검증-수락/거부하는 가속 기법. 출력 분포가 타깃 단독 실행과 동일함이 수학적으로 보장. 수락률이 높을수록 빠르다.
블록 확산 / DFlash 블록 드래프트
일반 드래프터(EAGLE 등)는 토큰을 하나씩 순차 추측하지만, DFlash는 확산(diffusion) 방식으로 8토큰 블록 전체를 한 번의 forward로 동시 생성한다. 구조화된 추론 문장의 블록 내 상관관계를 자연스럽게 포착.
Flow matching / 디노이징 / 속도장 / 중간 스텝 속도 캐싱
노이즈에서 목표 궤적으로 점진 변환하는 생성 기법. 매 스텝 "어느 방향으로 얼마나"(속도)를 예측하며 표준 10회 반복(디노이징). 속도장 = 스텝별 속도 예측의 집합. FlashDrive의 발견: 중간 스텝 속도가 거의 불변(코사인 유사도 0.99+) → 재계산 대신 이전 값을 캐싱·재사용해도 품질 유지.
W4A8 / W4A16 (양자화 표기)
W=가중치, A=활성값(중간 계산값)의 비트 수. W4A16은 가중치만 4비트 압축 → 메모리 로딩만 개선(디코딩 유리). W4A8은 활성값도 8비트 → INT8 정수 행렬곱 하드웨어 가속까지(프리필에도 유리).
이상치 (outlier)
가중치/활성값 분포에서 유독 큰 소수의 값. 낮은 비트 양자화 시 표현 범위를 낭비시켜 정밀도를 크게 떨어뜨린다. ParoQuant는 채널 쌍 회전으로 이상치를 분산·억제.
Marlin 커널 / bf16
Marlin: vLLM의 고성능 GPU 커널로 압축 가중치 행렬곱을 효율 실행. bf16(bfloat16): 16비트 부동소수점 — 여기서는 "양자화하지 않은 원래 정밀도"의 의미로, 오차에 민감한 action expert만 압축하지 않는다.
CUDA Graph / 커널 융합
CUDA Graph: GPU 커널 실행 순서를 미리 "녹화"해 통째로 재생 — 작은 커널 수백 개를 CPU가 하나씩 지시하는 오버헤드 제거. 커널 융합: 연속 연산(Q/K/V 프로젝션 등)을 한 커널로 합쳐 메모리 왕복과 실행 공백 제거.
Action expert / Cross-attention
Action expert: 언어 모델의 추론 결과를 받아 연속 주행 궤적을 생성하는 전용 서브네트워크. Cross-attention: expert가 VLM의 전체 출력(KV 캐시)을 참조하는 어텐션 — 캐시 전체를 통합하므로 작은 오차도 궤적에 크게 반영 = expert가 근사·양자화에 민감한 이유.
ADE / minADE
Average Displacement Error: 예측 궤적과 실제 궤적 사이 평균 거리 오차(m). @6.4s는 6.4초 예측 시계 기준. minADE는 여러 후보 궤적 중 최선의 오차. 낮을수록 좋다.
Forward (pass)
입력을 신경망에 한 번 통과시켜 출력을 얻는 것. LLM 추론 비용의 기본 단위 — "forward 16회" = 모델 전체를 16번 돌린다는 뜻.
메모리 바운드 vs 컴퓨트 바운드
속도를 결정하는 병목의 종류. 메모리 바운드 = 데이터를 메모리에서 읽어오는 시간이 병목(디코딩: 토큰마다 전체 가중치를 읽어야 함). 컴퓨트 바운드 = 연산량 자체가 병목(프리필: 수천 토큰을 한꺼번에 행렬곱). 최적화 수단이 달라서 구분이 중요 — W4는 전자를, A8은 후자를 푼다.
AWQ / W4A16
AWQ(Activation-aware Weight Quantization)는 널리 쓰이는 대표적 4비트 가중치 양자화 기법(2023). 가중치만 압축(W4A16)하므로 메모리 바운드인 디코딩만 빨라진다. FlashDrive에서는 ParoQuant의 비교 기준선.
EAGLE (계열)
현재 널리 쓰이는 speculative decoding 드래프터 계열. 토큰을 하나씩 순차 추측하는 자동회귀 방식이라 가속이 2~3×에 그친다 — 블록 단위로 한 번에 추측하는 DFlash의 비교 기준선.
vLLM / torch.compile / 정적 KV 캐시
vLLM: 가장 널리 쓰이는 오픈소스 LLM 서빙 엔진(Marlin 커널 제공). torch.compile: PyTorch의 자동 컴파일 기능 — 코드를 최적화된 GPU 커널로 변환. 정적 KV 캐시: 크기를 미리 고정 할당한 캐시 — CUDA Graph "녹화"의 전제 조건.
Ablation (기여도 분해 실험)
구성 요소를 하나씩 빼거나 바꿔가며 각각의 기여도를 측정하는 실험. "5개 기법 중 뭐가 얼마나 기여했나"를 증명하는 표준 절차. 현재는 streaming 미세조정 ablation만 공개됨.
End-to-end
인지→계획→제어를 별도 모듈로 나누지 않고, 입력(카메라)부터 출력(궤적)까지 신경망 하나가 통째로 처리하는 방식. 전통적 모듈식 자율주행의 반대 개념.
고유명사: Qwen3-VL / 10B / Jetson Thor / PhysicalAI-AV
Qwen3-VL: 알리바바의 오픈소스 비전-언어 모델 — Alpamayo 1.5의 베이스. 10B: 파라미터 100억 개(10 Billion). Jetson Thor: NVIDIA의 차량 탑재용 AI 컴퓨터 모듈. PhysicalAI-AV: NVIDIA가 공개한 자율주행 주행 영상 데이터셋(벤치마크에 100클립 사용).
DFlash / ParoQuant (Z Lab 선행 연구)
FlashDrive가 부품처럼 가져다 쓰는 같은 랩의 범용 LLM 가속 기법. DFlash(ICML 2026) = 블록 확산 기반 speculative decoding 드래프터. ParoQuant(ICLR 2026) = 채널 쌍 회전으로 이상치를 억제하는 4비트 양자화.
ICML / ICLR / CES
ICML(International Conference on Machine Learning)·ICLR(International Conference on Learning Representations)은 머신러닝/딥러닝 분야 최상위 국제 학회 — 여기 실렸다는 것은 동료 심사를 통과한 검증된 연구라는 의미. CES는 매년 1월 라스베이거스에서 열리는 세계 최대 IT·가전 전시회(Alpamayo 1 발표 무대).
Open-loop vs closed-loop 평가
open-loop: 기록된 주행 데이터에 대해 궤적 예측 오차만 측정(출력이 다음 입력에 영향 없음). closed-loop: 모델이 실제/시뮬레이션 차량을 직접 제어하며 누적 효과까지 평가 — 실전에 더 가깝지만 FlashDrive는 아직 open-loop 결과만 공개.
